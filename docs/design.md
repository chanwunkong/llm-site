# 設計文件（最小可行系統，2026-10-15 確認）

這是目前唯一的設計文件。舊版設計（`archive/design-v1.md`）太複雜：使用者說不出「我現在在做什麼」，既不像遊戲也不像練習。新版從確認過的原則重新建構。舊功能在程式裡全部**隱藏，不刪除**；舊文件移到 [archive/](archive/)，只供查歷史，不作為依據。

## 1. 原則

1. **目標**：能用目標語言正常溝通。學習動作和目標是兩件事。
2. **概念直達**：所有學習都是「意思 ↔ 目標語言」，不經過母語（不是「🐘 → 大象 → elephant」，而是「🐘 → elephant」）。依據：修正階層模型（Kroll & Stewart 1994）。
3. **基元是地基**：65 個 NSM 基元是最先學的字，也是描述其他意思的工具。
4. **所有東西都視為同一種**：不事先替字分類（不分基元、具體、抽象、有沒有圖示、實詞或功能詞）。
5. **只判斷形式**：系統只判斷目標語言說得對、寫得對，不判斷意思。意思是使用者自己的理解；每個人的理解不同，沒有標準答案，不能當遊戲規則。
6. **字和文法是一體**：一個字包含它所有的形式（eat、ate、eats）。文法的意思用基元表達（過去 → BEFORE NOW、否定 → NOT、複數 → MANY）。字讓你理解意思，文法讓母語者聽得懂你。
7. **不綁定任何語言**：所有語言走同一條路徑。
8. **不能靠猜**：每一級都要自己說出或寫出來，沒有選擇題。領土上的每一格都要是真的會（參考：Duolingo 的選項題可以靠排除法和直覺答對，成就感和能力脫鉤）。

## 2. 內容

- 學習資料由使用者匯入，系統負責拆解（斷句、UD 詞性、詞元、詞形特徵）。最一開始的 65 個字（基元 65）是起點。
- **理解由使用者自己寫**：用圖示（emoji）和已經會的字組合。剛開始什麼字都不會，就只能用圖示；會的字越多，就越能用字組合（例如 kitten = small + 🐱）。系統可以建議圖示，不判斷對錯。不同語言切分意思的方式不同（英文 kitten 是一個字，中文「小貓」是語塊），所以理解屬於使用者。

## 3. 內層：練習

- **一局 3 分鐘**（用時間結束，不是題數；時間到時，正在作答的那一題答完再結束）。
- 作答方式由使用者依當下場合選：**說**（發音評分服務判斷）或**寫**（字母卡或鍵盤）。
- **5 個等級**（每個字都一樣）：

| 等級 | 能力 | 你要做的事 | 提示 |
|---|---|---|---|
| Lv1 | 認識 | 第一次遇見，照著說或寫 | 字、朗讀、句子（有的話） |
| Lv2 | 理解 | 寫下自己的理解 | 你自己想 |
| Lv3 | 說出形式 | 從意思說出正確的形式 | 你的理解 ＋ 文法的意思（例如 MANY → cats） |
| Lv4 | 組合 | 從 2～3 個意思，照正確的順序和形式說出一小段 | 幾個理解組合在一起（順序打亂） |
| Lv5 | 新的情境 | 在沒看過的新句子裡用出來 | 新的句子 |

- **為什麼 Lv2～Lv4 不用句子**：大部分的字在一份資料裡只出現一兩次（齊夫定律），一直用同一句會變成背句子（情境依賴）。句子只用在第一次遇見（Lv1）和新的情境（Lv5）。
- **記憶是每一級的條件**：升級要在**不同的天**再答對一次才算數（Lv2 寫下理解即完成）。太久沒練就降一級：Lv3 3 天、Lv4 7 天、Lv5 14 天。
- **Lv4 的答案**只用資料裡實際出現過的組合（例如資料裡有 "small cat"）。系統不自己造組合。
- **Lv5 的新句子**：這個字出現在還沒用它練習過的句子，任何來源都算。沒有新句子時，等使用者匯入更多資料。
- **成就感**：答對就是「我理解了、我做得到」的證明。內層不追求緊張感。

## 4. 外層：領土

- **領土是能力本身的具象化**。字到 Lv2 就長出一格，等級越高格子越高；太久沒練會變低、變暗。
- 玩家自己擺放。擺放**暫時沒有獎勵**（之後再設計；關係的依據會是使用者自己寫的理解）。

## 5. 發音

- 說出來時由發音評分服務判斷（每個音都評分），並記錄（見第 8 節）。
- 使用者家裡的服務只是內部測試；未來改用公開的線上服務。沒有服務時暫時用手機的語音辨識。

## 6. 預設（使用者沒有反對，之後可調）

| 項目 | 預設 |
|---|---|
| 一局出哪些字 | 先出到期該練的字（等著「不同天再答對」或快要降級），剩下的時間教新字；新字照來源的順序 |
| 新字 | 每局先教 3 個；到期的字都做完、時間還沒到，就繼續教新字（照來源的順序） |
| 升級之後 | 同一局稍後接著做下一級（例如到 Lv2 就接著寫理解） |
| 寫出來怎樣算對 | 拼法完全相同，不分大小寫 |
| 說出來怎樣算對 | 評分服務判斷唸的是這個字；難音不準只是回饋 |
| 寫理解的畫面 | 系統建議幾個圖示，可以搜尋 emoji，也可以用 Lv2 以上的字 |
| 文法的意思 | 先做：過去（BEFORE NOW）、複數（MANY）、否定（NOT）、問句（?）。Lv3 只出單一個字的變化（過去、複數）；否定和問句出現在 Lv4 的組合裡 |
| 存檔 | 新版用新的存檔，舊的進度保留在舊存檔，不覆蓋 |

## 7. 之後再決定

- 擺放的獎勵。
- 語序以外的文法（例如格位、一致）怎麼放進文法的意思。
- 連鎖、WALS 規則、星數、王關等舊功能要不要回來、怎麼回來。

## 8. 沿用的技術元件

以下是舊版做好、新版繼續使用的部分。

### 8.1 學習資料的拆解
- 斷句 → UD 詞性、詞元、詞形特徵（`feats`，例如 `Tense=Past`、`Number=Plur`）→ 句法分析（依存關係）。所有語言用同一套 UD 標記。
- **網頁匯入**（首頁「＋ 匯入文章」）：貼上文字或選 .txt 檔。多數語言用 UDPipe 線上服務（模型限非商業使用）；日文用瀏覽器內的 kuromoji.js（讀音用發音假名）；孟加拉語、史瓦希里語沒有 UD 模型，用瀏覽器內建斷詞（沒有詞性）。匯入的內容只存在使用者的瀏覽器裡。
- 內建示範由本機腳本 `data/sources/decompose.py` 產生（公版作品），網站啟動時依清單載入。**示範資料不寫進程式碼**：原文在 `data/sources/raw/`，語言設定只放在 `site/js/data/langs.js`（21 種語言）。

### 8.2 基元 65
- 21 種語言都有 65 個基元的對應字：`data/concepts/nsm-exponents.csv`（英文是 NSM 標準寫法，其他語言是草稿，要母語者確認）。
- 每個基元有建議的 Emoji（`data/concepts/nsm-primes.csv`）：以 Emoji 為主，一個不夠準確時用兩個組合，不用自創符號。新版中它們只是「寫理解時的建議」，使用者可以改。
- 資料檔 `site/data/core/<語言>.json`（`data/concepts/build_base.py` 產生；音標 `ipa` 由 `data/phonology/build_phonology.py` 加上，要在 build_base 之後執行）。

### 8.3 朗讀（全部在手機上完成，不連語音伺服器）
- 順序：1) 手機有這個語言的語音就用；2) Piper（神經網路語音，聲音檔第一次從官方 Hugging Face 庫 rhasspy/piper-voices 下載，每種語言約 60～73 MB，存在 OPFS；17 種語言）；3) eSpeak NG（WebAssembly，GPL-3.0，`site/vendor/espeak-ng/`）。
- 替代聲音：設定 → 朗讀聲音，吉爾吉斯文可以改用土耳其文或俄文的聲音（文字先轉寫，`js/engine/translit.js`）。

### 8.4 音標
- 各語言的音位清單：PHOIBLE 2.0（CC BY-SA 3.0）。內建資料的字用 eSpeak NG（英文等）、pyopenjtalk（日文）產生 IPA。
- 匯入的文章在手機上產生 IPA（eSpeak NG WebAssembly；日文用發音假名轉換），再依音位清單切成音。
- 發音頁（IPA 表）：和「我會的語言」比較，標出難音（目標語言有、我會的語言都沒有的音）；可以聽單音錄音（維基共享資源）和相近的音比較。

### 8.5 發音評分服務（`services/pronounce/`，介面見 `API.md`）
- 學習者在「設定 → 發音評分服務」填網址與存取密碼（只存在這台裝置；錄音只送到這個服務，不保存錄音）。
- **服務的階段**：現在是使用者家裡的內部測試（只在 Tailscale 私人網路，網址和密碼不寫進公開的程式）；未來改用公開的線上服務（雲端主機、瀏覽器內執行或社群服務清單，都不使用使用者家裡的設備），遊戲預設填入公開服務的網址。介面統一，換方式只換網址。
- **所有口說都由服務判斷**。服務只分析一次錄音，可以一次比較多個候選（1.1.0 起），正確答案的機率 ≥ 0.25 就算唸了正確答案（難音不準是回饋，不算錯）。只有一個答案時，用拼法最接近的 3 個字當候選（包含或被包含的字優先，例如 some／something）。
- **每個音都評分**（1.2.0 起，`per_phone`）：每個位置空出來判斷，候選用這段錄音裡模型聽得最清楚的 15 個音，加上預期的音和「漏掉」。
- 支援 19 種語言（越南語、泰語暫不評分；中文只評子音）。不評分：重音、聲調、長短。
- 只用合成語音測過；真人聲音的準確度待測。

### 8.6 發音紀錄（`js/engine/pronlog.js`，IndexedDB）
- 只記錄評分服務的結果，不存聲音。**一次錄音存一筆，照順序存下每個音的結果**（預期的音、聽到最像的音、機率）。原始紀錄留最近 2,000 筆（約 300 KB），統計每次更新、永久保留。
- **三層統計**：單一的音（次數、正確率、最常唸成哪個音）；音的排列（位置、前後是母音或子音；至少 5 次才判斷）；單字本身（每個位置各自的錯誤紀錄）。
- 顯示：最近 5 次、最近 10 次的平均、全部；最近比全部好時顯示「進步中」。一局結束顯示這局要注意的音；發音頁列出最需要注意的 3 個音，IPA 表依正確率加色帶，點一個音看三層紀錄。
